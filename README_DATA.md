# Исследование влияния динамической топологии графа на прогноз временных рядов

Курсовая работа на тему **«Исследование влияния динамической топологии графа на качество прогноза временных рядов в гибридных моделях вида LSTM-GNN»**.

Научный руководитель — Губанов Д. А.

В этом документе описаны источники данных, их получение, обработка и временные разбиения. Используются три набора: синтетические ряды, дорожные скорости METR-LA и финансовые данные Московской биржи.

## 1. Общая структура данных

Вершине соответствует отдельный временной ряд. Для каждого момента времени сохраняется один числовой признак каждой вершины.

| Набор | Вершина | Признак | Временной шаг | Размер подготовленной панели |
|---|---|---|---|---:|
| Синтетика | Узел сгенерированного графа | Состояние узла | Шаг генератора | 6001 × 12 |
| METR-LA | Дорожный датчик | Скорость транспортного потока | 5 минут | 34272 × 207 |
| MOEX | Акция | Логарифм внутрисессионной реализованной дисперсии | Торговая сессия | 1503 × 10 |

Размер панели указан как «число временных строк × число вершин». Пропущенные значения сохраняются внутри панелей, поэтому размер таблицы не равен числу наблюдаемых значений.

## 2. Синтетические данные

Синтетика создаётся локально. Она задаёт контролируемый случай, в котором известны истинные связи между рядами и закон генерации наблюдений. В текущем наборе истинный граф постоянен.

### Построение графа

Создаётся направленный взвешенный граф из 12 вершин, разделённых на три группы по четыре вершины.

Для каждой вершины случайно выбираются от двух до четырёх различных входящих соседей. Собственная вершина исключается. При выборе соседей кандидатам из той же группы назначается вес выбора 3, остальным — 1; выбор выполняется без возвращения.

Первоначальные веса выбранных рёбер берутся из равномерного распределения на отрезке [0.2, 1.0], затем нормируются по строке. Таким образом,

$$
A_{ij}\geq 0,\qquad A_{ii}=0,\qquad \sum_j A_{ij}=1.
$$

Здесь $A_{ij}$ обозначает влияние вершины $j$ на вершину $i$. Нулевое значение означает отсутствие ребра.

### Генерация рядов

Состояния изменяются по правилу

$$
x_{t+1}=\alpha x_t+\beta A x_t+\varepsilon_t,
\qquad
\varepsilon_t\sim\mathcal{N}(0,\sigma^2 I).
$$

Обозначения: $x_t$ — вектор состояний 12 вершин; $\alpha$ — коэффициент собственной инерции; $\beta$ — коэффициент влияния соседей; $\sigma$ — стандартное отклонение независимого гауссовского шума.

Использованная конфигурация:

| Параметр | Значение |
|---|---:|
| Число вершин | 12 |
| Число групп | 3 |
| Число входящих соседей | От 2 до 4 |
| $\alpha$ | 0.4 |
| $\beta$ | 0.3 |
| $\sigma$ | 0.1 |
| Seed генерации | 42 |
| Предварительных шагов | 200 |
| Сохраняемых переходов | 6000 |

Начальное состояние задаётся нулевым вектором. Первые 200 переходов отбрасываются. Затем сохраняются состояние после этого периода и ещё 6000 переходов — всего 6001 строка. Для построения графа и шума используются отдельные потоки случайных чисел, полученные из общего seed.

В исходном CSV столбец `step` содержит номера шагов от 0 до 6000, а `node_0` … `node_11` — состояния вершин. Матрица истинного графа сохраняется отдельно. При подготовке разбиений исходная реализация считывается без повторной генерации.

## 3. METR-LA

### Источник и скачивание

METR-LA содержит временные ряды скоростей транспортного потока на дорожных датчиках Лос-Анджелеса. Используется исходный файл `metr-la.h5`, доступный по ссылке авторов в [репозитории DCRNN](https://github.com/liyaguang/DCRNN#data-preparation).

Дополнительно скачиваются опубликованные авторами матрица дорожного графа, идентификаторы датчиков и их координаты. Исходные файлы сохраняются без изменения содержимого; рядом записываются URL, размер, время получения и SHA-256. Контрольные суммы зафиксированы по локально проверенному снимку файлов, а не взяты из опубликованного авторами списка хешей.

Данные охватывают **1 марта — 27 июня 2012 года**. Сохраняются все 207 датчиков, исходные единицы скоростей и временные метки с шагом пять минут.

### Обработка

1. Проверяются уникальность идентификаторов датчиков, порядок и уникальность временных меток.
2. Проверяется соответствие временных меток пятиминутной сетке.
3. Нули, отрицательные и неконечные значения скорости помечаются как пропуски.
4. Если в общей временной сетке отсутствует строка, она добавляется с пропущенными значениями.
5. Сохраняются исходные положительные значения скоростей и маска наблюдаемости.

Считать нули пропусками — принятое правило обработки этого набора. Оно не устанавливает причину каждого отдельного нулевого показания. Часовой пояс исходных меток дополнительно не назначается.

## 4. Финансовые данные Московской биржи

### Источник и скачивание

Источник — [Информационно-статистический сервер Московской биржи, ISS](https://iss.moex.com/iss/reference/).

Период выгрузки: **01.01.2020–31.12.2025**, режим торгов **TQBR**.

Сначала собирается исторический список инструментов, пересекающихся с выбранным периодом, и список инструментов из дневной истории торгов. Далее скачиваются:

- спецификации и идентификаторы инструментов;
- дневная история торгов;
- сведения о границах доступной истории;
- десятиминутные свечи с ценами OHLC, объёмом и оборотом.

Перечень бумаг формируется по историческим данным, включая инструменты, которые позднее перестали торговаться под прежним идентификатором. Внутридневная история скачивается отдельными месячными задачами.

Исходные ответы ISS сохраняются в сжатом кэше вместе с параметрами запросов и контрольными суммами. Сохранённые ответы используются при повторной обработке. Завершение плана выгрузки означает выполнение запросов; полнота полученной истории проверяется отдельно.

### Отбор акций

Покрытие истории и ликвидность оцениваются **только по периоду 2020–2023 годов**. Тип бумаги и эмитент определяются по сохранённому снимку спецификаций. Используются следующие условия:

1. Обыкновенная акция с известным эмитентом и рублёвыми торгами на TQBR.
2. Положительный дневной оборот не менее чем для 95% ожидаемых полных рыночных сессий train.
3. Корректная полная внутридневная история не менее чем для 95% этих сессий.
4. Положительный медианный оборот в рублях за используемое внутридневное окно.

Медианный оборот рассчитывается по корректным полным внутридневным дням train. Прошедшие фильтры бумаги ранжируются по этому показателю. Выбираются десять бумаг, не более одного выпуска на эмитента:

`SBER`, `GAZP`, `LKOH`, `GMKN`, `YNDX`, `ROSN`, `PLZL`, `MGNT`, `NVTK`, `VTBR`.

Причины исключения остальных кандидатов сохраняются в аудите отбора. Доступность данных в val/test не используется для изменения состава.

### Расчёт реализованной дисперсии

Для каждой акции и рыночной сессии используется окно **10:00–18:40 по московскому времени**: 52 свечи с началами от 10:00 до 18:30.

Обозначения: $p_{i,d,0}$ — цена открытия первой свечи акции $i$ в день $d$; $p_{i,d,k}$ — цена закрытия свечи $k$. Тогда

$$
r_{i,d,k}=\log\left(\frac{p_{i,d,k}}{p_{i,d,k-1}}\right),
\qquad
RV_{i,d}=\sum_{k=1}^{52}r_{i,d,k}^{2}.
$$

Первая доходность учитывает изменение от открытия первой свечи до её закрытия; последующие — между соседними закрытиями. Ночная доходность в эту сумму не входит.

Основной финансовый признак:

$$
z_{i,d}=\log\left(\max\left(RV_{i,d},10^{-12}\right)\right).
$$

Исходная RV сохраняется отдельно без применения нижнего порога. Объём, оборот, внутрисессионная доходность и диапазон цен сохраняются в отчётах обработки. В общую панель признаков входит один ряд log(RV) на акцию.

### Контроль качества и календарь

Проверяются точная сетка свечей, корректность времён, конечность и положительность цен, согласованность OHLC, неотрицательность объёма и оборота. Одинаковые дубликаты удаляются; конфликтующие дубликаты делают день невалидным.

Неполная или некорректная сессия получает пропуск с указанием причины. Экстремальные ценовые движения сохраняются, если проходят проверки корректности.

Общий календарь восстанавливается по наличию положительного дневного оборота обыкновенных акций TQBR. Сокращённые сессии **24–30 марта 2022 года** остаются в календаре, но не используются как полные дни расчёта RV. Перерыв более семи календарных дней начинает новый сегмент; окна через такой разрыв исключаются.

Поле `time` для MOEX содержит дату сессии. RV этой даты становится доступна после окончания выбранного внутридневного окна.

Спецификации инструментов сохранены как снимок на момент выгрузки. Истории разных SECID автоматически не объединяются; переименования и корпоративные события отдельно не корректируются. После изменения доступности бумаги могут оставаться пропуски в её столбце; например, у YNDX нет наблюдаемых целей в тестовом периоде.

## 5. Общий формат и временные разбиения

Подготовленные данные хранятся в `data/processed/`. Для каждого набора выделены части `train`, `val`, `test`.

| Файл внутри части | Содержание |
|---|---|
| `series.csv` | Столбец `time` и один столбец признака каждой вершины |
| `raw_values.csv` | Значения в исходной шкале; для MOEX — RV |
| `observed_mask.csv` | Исходная наблюдаемость: 1 — значение есть, 0 — пропуск |

Строки упорядочены по времени, порядок вершин фиксирован между частями. CSV сохраняют пропуски и ненормированные значения.

Рядом с частями сохраняются схема данных, общий календарь с идентификаторами сегментов, индекс допустимых примеров, обучающие средние и manifest с настройками и контрольными суммами.

Разбиение хронологическое:

- синтетика и METR-LA: **70% train / 10% val / 20% test**;
- MOEX: **2020–2023 годы — train, 2024 — val, 2025 — test**.

## 6. Окна, пропуски и маски

Один пример содержит историю **60 наблюдений** и цель на следующий шаг. Для MOEX следующий шаг соответствует следующей общей рыночной сессии.

В CSV перекрывающиеся окна заранее не размножаются. При формировании примера используются формы

$$
X\in\mathbb{R}^{60\times N\times 1},
\qquad
y\in\mathbb{R}^{N},
$$

где $N$ — число вершин. Для группы из $B$ примеров добавляется первая размерность $B$.

Пример сохраняется, если для него хватает истории, история и целевой момент находятся внутри одного сегмента и существует хотя бы одна наблюдаемая цель. Наличие целей всех вершин одновременно не требуется.

Для первых примеров val/test разрешена предшествующая история из более ранних частей. При этом целевые значения относятся к своей части; будущие относительно момента прогноза значения во вход не включаются.

Правила обработки пропусков при формировании окна:

1. Входы заполняются последним наблюдаемым значением **внутри этого окна**.
2. Если такого значения ещё нет, используется среднее соответствующей вершины по train.
3. Цели сохраняют пропуски. Маска целей отмечает, для каких вершин есть настоящий ответ.
4. Исходная маска входов сохраняется отдельно, поэтому заполненные значения можно отличить от наблюдавшихся.

Нормировка при формировании примеров использует среднее и стандартное отклонение каждого ряда, рассчитанные только по наблюдаемым значениям train. В сохранённых CSV нормировка не выполнена.

## 7. Воспроизводимость подготовки

Сохраняются параметры скачивания, исходные ответы источников, контрольные суммы, выбранный состав вершин, причины брака и правила разбиения. Для синтетики фиксируются seed, параметры процесса и матрица истинного графа.

Проверка SHA-256 позволяет установить, что повторная обработка использует тот же снимок данных. Исходные и обработанные данные остаются локальными; описания и настройки позволяют документировать их происхождение.
